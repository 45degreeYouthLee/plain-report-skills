# 持续交接：同一项目的多轮汇报

同一个项目会被反复汇报、换人或换会话接手时用。读者要的不是更全的记录，而是三件事：**看懂项目到哪了、一眼看出这轮变了什么、知道下一步谁做什么**。

做法：把项目拆成稳定的对象（环节、事项、决定、人类动作），每轮只写一个"变更批次"（事件文件），页面由 `report-page-style` 的交接构建器生成。不要每轮重写一整套相似的卡片。数据格式见 `report-page-style/references/handoff-data.md`。

## 第一次建交接

1. **先读懂项目，再拆对象。** 读项目自己的说明（README、架构文档、验收标准），写 `project.json`：
   - `goal`：服务谁、解决什么，一句话。
   - `phases`：项目怎样算做成，拆 2–4 个环节，每个写现在证明到哪（`summary`）和还缺什么证据（`gap`）。环节是产品能力，不是工作流程。
   - `mechanics`：各环节怎样配合，每条一句大白话。
2. **区分产品和支撑工作。** 每个事项标 `track`：`product`（产品能力本身）或 `support`（测试环境、权限、工具、文档、交接）。支撑工作完成不等于产品通过。
3. **按时间把已有汇报转成事件。** 一份汇报一个事件，按发生顺序编号。早期事件只写当时知道的事，不用后来的结果改写，不出现"后续""最终"这类回看的词。

## 每轮更新

1. **读本轮新材料，判断改变了哪个对象：** 新增、更新、复核、更正还是撤回。什么都没变就不发新一轮。
2. **只写受影响的对象。** 事件里只放变化的字段，其余自动沿用。用 `change.kind` 说明变化类型，用 `change.impact` 写这个变化的后果（推迟、解锁、增加什么）。
3. **整体判断变了才写 `overview`。** 只动了支撑工作时不要改整体判断；页面会自动提示"产品本身这一轮没有新证据"。
4. **连带更新：** 已裁决的条件从待决定和追问里删掉；被撤回的建议对应的动作停掉（`active: false`）；被新证据推翻的说法用更正事件取代，旧记录留在历史里。
5. **排下一步：** 给每个未完成事项的 `action` 写做什么、交付什么、怎样算完成；用 `priority` 排先后，最关键的一项标 `1`，写 `unblocks`（做完能解锁什么）。资料里没有负责人就留空，页面显示"待分派"。
6. **真有开放问题才发起决定：** `status: "待决定"`，至少两个选项，每个写得到什么、代价、风险，再写推荐、改选条件、怎么回复。已定的事不再发起。
7. **构建并处理提示：** 运行构建命令。数据错误会直接报错；文字提示（含路径编号、否定词过多、影响复述事实、没标最关键动作）逐条修改，确需保留的在交付说明里写原因。
8. **记录维护成本：** 在交付说明里写本轮改了哪些文件、读资料和归纳用了多久、有没有返工。构建脚本的运行时间不算维护时间。

## 发布前检查

逐项过，任一项答"否"就先改：

- **读者五问：** 只看最新一轮的第一屏，能答出整体到哪、这轮变了什么、最关键的下一步、要用户做什么、已定了什么吗？（可以只读生成的 `.fact.md` 最上面一段来自测。）
- **没有重复索要：** 已裁决的条件不在待决定、缺项或追问里出现。
- **撤回不残留：** 已撤回的建议不在任何当前动作里。
- **变化真实：** "这一轮变了什么"里的每一项都真的变了；产品没新证据时，标题没有把支撑工作说成产品进展。
- **时间诚实：** 每个事项显示它自己的最后证据时间，不被页面更新时间刷新；早期截点没有回看的说法。
- **局部不升级：** 一个专项通过没有写成整个环节或整个项目通过。
- **页面能用：** 在真实浏览器里点时间线、按后退和前进、直接改地址里的 `#v2`、打开一个证据链接再刷新，所选轮次和正文一致；手机宽度（约 400px）没有左右滚动。没测的写"未测"。
- **页面只讲项目：** 制作过程、技能修改、测试数量、"待用户验收"这类话不进报告页面，放到交付说明里。

构建器只能检查结构和已编码的关系（稳定 ID、来源存在、已裁决条件、撤回依赖）；文字是否讲清楚要靠这份清单。

## 交付时在聊天里写什么

- 页面路径，加一句整体结论。
- 本轮改了哪些数据文件；没处理的文字提示及原因。
- 哪些检查做了、哪些没做（如"未在真实浏览器测试"）。
- 要核对：1–3 件用户应该自己核对的事。

## 可选：交给其他 Agent 核对

页面末尾的核对包包含最新截点的主张、来源和只读范围。用户想要第二意见时复制给其他 Agent；结果按"有证据支持 / 与证据冲突 / 证据不足"返回。核对是可选的，不把制作者的自检推给用户。
