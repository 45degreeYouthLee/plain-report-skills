# 动画（扩展项，不默认）

来源：visual-explainer 的 motion.md（分步播放、回放），按 GG 的要求改成扩展项。

## 什么时候用

只在静态图讲不清时用。典型情况：

- **架构演示：** 一个请求依次经过哪些组件，在哪里分叉、在哪里失败。
- **状态机和工作流：** 一次真实运行中，状态怎么一步步变化、为什么这样变。
- **队列和资源池：** 任务怎么排队、被取走、超时重试。
- **架构演进：** 从现在的结构一步步变成目标结构。

不用的情况：
- 静态图已经能一眼看懂。
- 只是想让页面"动起来"。
- 装饰性的循环动画、视差滚动、自动播放。

## 两种形式

### 分步播放

一张图分成若干步，每步亮起一部分，配一行说明。

- **打开时停在最后一步，即完整的图。** 读者先看到全貌，点"从头播放"才逐步演示。这样不违反"交互不隐藏信息"。
- **每步只讲一件事，** 每步图上都要有看得见的变化。
- **控件：** 上一步、下一步、播放、进度条；显示"第 3 / 7 步"。
- **从不自动播放。**

### 回放

用于状态机、工作流：每一步是一个事件。

- **说明写"发生了什么、为什么"：** 如"缓存未命中 → 查数据库，因为 TTL 已过期（cache.ts:48）"。"为什么"必须引用真实的条件或代码位置，不编造。
- **选 6–12 个事件，** 讲清一个论点。另一个分支另做一个回放，或画成并排小图。
- **整台状态机一直画着，** 回放只点亮当前触发的边和节点。
- **事件来自真实运行时，** 在图注里写明来源。

## 实现规则

- **用 `report-page-style` 里的 stepper 组件**（`assets/template.html` 的"分步播放"示例），不自己从零写。
- **只动 `transform`、`opacity`、`stroke-dashoffset`。**
- **系统设置了"减少动态效果"时，** 直接显示最后一步的完整图。
- **打印和不支持脚本时，** 也显示完整图。
