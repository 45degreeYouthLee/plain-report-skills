# 页面

页面的样式、组件和模板在 `report-page-style` 里；本文件只管页面的内容结构和布局判断。

来源：visual-explainer 的 SKILL.md 和 style-guide.md；agent-html-skills 的研究报告、时间线、架构图 skill 和它们共用的"HTML 输出基础"；GG 的反馈。

## 结构

- **第一屏就是答案：** 一句结论，加一张全景表或全景图，把所有对象和关系摆出来。
- **先全景，后细节：** 读者往下看、点开 `<details>`，才看到原始材料；但来源列表始终放在页面底部，不折叠。

| 页面类型 | 顺序 |
|---|---|
| 进度汇报 | 结论 → 全景（各模块状态）→ 本次变化 → 阻塞 → 需要决定 → 要核对 |
| 决策请求 | 推荐 → 选项并排（做法、牵连、成本、风险）→ 翻转条件 → 怎么回复 |
| 评审、审计、整合说明 | 判定 → 全景 → 逐项证据 → 风险 → 需要决定 → 要核对 |
| 事故复盘 | 结论 → 时间线 → 根因 → 做对的 → 做错的 → 后续动作 |
| 方案或技术对比 | 差别（并排画出）→ 取舍 → 推荐 → 需要决定 |
| 概念或架构讲解 | 问题 → 全景图 → 机制（必要时分步播放）→ 边界情况 → 要记住的 |
| 路线图、进度时间线 | 时间轴 → 各条工作线 → 依赖 → 里程碑（见下） |
| 验收清单 | 按使用流程分组 → 每步做什么、应看到什么 → 结果回填 |

- **超过 4 节才加目录导航。**
- **页面底部写更新时间和依据来源。** 会被反复打开的页面（架构图、路线图、进度）尤其要写。

## 布局判断

- **先判断是不是在对比。** 多个对象做同一类事、比同一组维度，才用表格（行是对象，列是维度）。各做各的事时，一个对象一张卡片，每张卡片按自己的内容组织。
- **布局跟着内容量走。** 卡片大小、列宽按文字多少分配。避免大片留白，也避免窄列里塞长段文字。
- **交互只高亮和筛选，不隐藏。** 不用下拉框、标签页、逐步点击来"揭示"信息。分步播放例外，但它打开时必须停在完整的图上（见 `motion.md`）。
- **每屏一个主角：** 一个最显眼的元素，一两个次要元素，其余是安静的文字。
- **节奏要变：** 宽图 → 数字条 → 并排小图 → 短文字。不要连续三块长得一样。
- **区隔的顺序：** 先用空白，再用细线，最后才用边框。卡片里不套卡片。
- **手机宽度（约 400px）也要能读：** 多列在窄屏变单列，不出现左右滚动条。

## 路线图和时间线

- **时间诚实：** 按月规划就不写到具体某天。
- **"今天"标线：** 时间线跨过今天时必须画。
- **依赖箭头只画真依赖：** 后一项必须等前一项完成，或跨团队交接。挨得近不算依赖。
- **注释挂在具体日期上：** 如"10-24 列表问题定位"。
- **手机上时间轴改成竖向。**

## 安全

页面会被转发，按"会离开本机"处理：

- **引用代码、配置、日志、命令输出前，** 把密钥、令牌、密码、带签名的链接换成 `<REDACTED:类型>`。
- **发现真实密钥时，** 页面里替换掉，同时告诉 GG 去更换它。
- **页面里不嵌入用户数据、本机证据目录的绝对路径。**
- **把引用内容插进页面时用 `textContent`，** 不用 `innerHTML` 拼接变量。

## 成本

- **模板加数据：** 从 `report-page-style/assets/template.html` 开始，只换内容；更新已有页面时只改变化的部分。
- **不重复输出：** 页面写过的内容，聊天里只给结论和链接。
- **能截图时截图看一眼，** 修一轮再发，不反复截图。
